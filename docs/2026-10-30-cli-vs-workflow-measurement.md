# `--claude-via cli`와 Workflow 경로 비교 실측 (2026-10-30)

`docs/2026-10-30-claude-via-cli-endtoend-measurement.md`(PR #44)가 못 한 두 가지를 쟀다. (1) 같은 표본을 `--claude-via` 없이(Workflow 경로) 돌려 CLI 경로와 쌍으로 견주기, (2) 판가름·Claude 의견이 실제로 도는 표본으로 CLI 경로(`adj-cli.json`·`opinion-cli.json`)가 타는지와 비용 재기. 코드는 바꾸지 않았다.

## 요약

- **쌍 비교(지적 1건, 각 1회): Workflow 경로 $1.71(메인 $0.64 + 작업자 $1.07), CLI 경로 $1.03(메인 $0.54 + 작업자 $0.49).** 그러나 CLI를 나중에 돌려 캐시가 데워진 상태였다. 재검토(Workflow, Fable 5.1)가 $0.85 대 $0.43으로 갈린 것이 차이의 큰 몫이고, 이 재검토는 두 경로 모두 Workflow라 경로 효과가 아니다. 경로 효과로 볼 수 있는 부분은 재검토를 뺀 1단계 작업자 비용(Workflow $0.22, CLI 이번 $0.07, PR #44의 차가운 CLI $0.16)이다. 이 값도 캐시 상태에 따라 움직인다.
- **같은 표본에서 호출당 캐시 쓰기는 Workflow 에이전트가 6.2만~6.5만 토큰, `claude -p`는 이번 실행에서 약 1만 토큰(PR #44의 차가운 첫 호출은 3.4만~3.6만)이었다.** PR #44의 「`claude -p` 호출마다 3.4만 이상」은 호출마다 고정이 아니라 캐시가 차가울 때(첫 호출)의 값일 가능성이 크다(가설).
- **판가름·의견의 CLI 경로는 실제로 탔다**(`adj-cli.json`·`opinion-cli.json` 생성, 호출 비용은 `claude-usage.json`의 `cli-adj-1`·`cli-opinion-1` 행). 판가름(Opus 5.5) $0.33, 의견(Fable 5.1) $0.83이었다. 이 표본에서 의견 한 번이 작업자 합계($0.12)의 약 7배다.
- 1회씩이라 통계 결론은 없다. 메인 세션이 같은 세션이라 맥락 길이·캐시 상태·실행 순서가 경로와 섞여 있다.
- 측정 구간 합계는 $4.91로 승인 상한 $5 안이다(쌍 비교 $2.75 + 판가름·의견 표본 시도 3회 $2.17). 한도·로그인 문구는 어디서도 나오지 않았다.

## 2단계: 판가름·의견이 걸리는 표본

`adopt_on_both_pass`가 켜진 `claude-only`는 같은 판정에 패치만 다르면 판가름 없이 채택하므로, 임시 프로필 `cfx`(`base = "claude-only"`, `adopt_on_both_pass = false`)를 `repos.toml`에 넣어 썼다(복원됨). `--claude-via cli --max-rechecks 0`(재검토 Workflow 비용을 빼 상한 안에 두려고 재검토를 껐다. 이 단계는 재검토 비용이 빠진 값이다).

작업자 둘(Sonnet 5.5 low·Haiku 5.5 low)이 갈리는 표본은 의도대로 만들어지지 않았다. 시도 3회:

| s2 (3건) | percent의 0 나누기(사실), slugify 소문자(사실 아님, 거짓 지적), parse_price 쉼표(설계 결정 후보) | 합의-사실 1(적용), 합의-아님 1, 합의-설계결정 1 | 0 | 0 | $0.18 | $0.17 | $0.36 |

- 사실·사실 아님·설계 결정 세 부류 모두 작업자 둘이 같은 판정에 도달했다. 판가름이 타려면 패치가 달라야 하는데, 갈리는 쪽은 s4의 제너레이터 지적 하나에서만 나왔다.
- s4-x2: 작업자 둘이 모두 「사실」이고 패치가 달라(a·b) 판가름(CLI, Opus 5.5)으로 갔다. Opus는 b 패치를 골랐지만 「판가름 패치 검증 실패」·「둘 다 검증 실패」라 사람 목록의 판단 불가가 됐고, Claude 의견(CLI, Fable 5.1)이 붙었다(「판정에 동의한다」). 라운드 폴더에 `adj-cli-args.json`·`adj-cli.json`·`opinion-cli-args.json`·`opinion-cli.json`이 생겼고 Workflow는 쓰지 않았다.
- 판단 불가의 사유는 판정 문제가 아니라 표본 탓일 가능성이 크다(추정). 이 표본은 쌍 비교와 같은 저장소를 복사해 `test_average_of_values`가 기준선에서 이미 실패하고, `tests {files}`가 그 파일 전체를 돌려 패치와 무관하게 검증이 실패한다. 의견도 「maximum 관련 2개는 통과한다」고 적었다. 저장소를 지운 뒤라 `verify.json`으로 확인하지 못했다. 그래서 「판가름→의견」 꼬리가 탄 것은 사실이지만, 실제 설계 쟁점 때문에 탄 것은 아니다.

## 미확인

- 캐시 상태가 경로와 분리된 비교(차가운 쪽끼리, 또는 실행 순서를 바꾼 반복). 한 번씩이라 순서 효과를 분리하지 못했다.
- 캐시 쓰기 크기의 원인(모델별 프리픽스 공유, TTL 구성). 위 설명은 숫자가 맞는다는 정도이고 로그로 확인하지 않았다.
- 판가름·의견의 Workflow 경로 비용(같은 표본). 그래서 「판가름·의견은 CLI가 싸다·비싸다」는 말할 수 없다.
- s4-x2의 검증 실패 원인(기준선의 기존 실패 때문이라는 추정은 `verify.json` 확인을 못 했다).
- 메인 비용·요청 수의 경로별 차이. 알림 확인·진행 설명이 구간에 섞였다.
- 한도(usage limit)·로그인 만료 문구는 이번에도 나오지 않아 여전히 미확인이다. 어느 호출에서도 실패·대체 실행은 0건이었다.
- Haiku 장문 단가 적용 여부(PR #44와 같다).

## 해석(가설)

1. 1단계 작업자만 보면 `claude -p`가 Workflow 에이전트보다 호출당 캐시 쓰기가 적어 작업자 비용이 낮을 수 있다(차가운 대 차가운 약 26%, 데워진 경우 더 낮음). 지적 1건 한 번이라 경로 효과를 단정하지 못한다.
2. 합계에서 큰 몫은 경로와 상관없는 재검토 Workflow($0.43~0.86)와 의견(CLI여도 $0.83)이다. Fable 5.1이 쓰이는 호출은 캐시가 차가울 때 호출당 $0.8대로 비싸다. 이 모델을 쓰는 칸이 비용의 지배 요인이라는 가설이 이 표본과 맞는다(판가름 Opus $0.33 대 의견 Fable $0.83).
3. 메인 진행 비용은 두 경로 모두 $0.5대로 PR #44의 $0.25보다 높았지만 구간에 비경로 요청이 섞여 있고 맥락도 더 길어(157k~170k) 경로 효과로 해석하지 않는다.
4. 판가름에 닿으려면 작업자 판정이 갈리거나 패치가 달라야 한다. 이 표본에서는 단순·거짓·정책 충돌 지적은 모두 합의로 끝났다. 판가름·의견이 걸리는 비율은 실제 리뷰 지적에서 재야 한다.

## 코드 변경 제안(이 PR에서는 하지 않음)

- 판단 불가 사유에 「검증 실패가 기준선에서도 실패한 테스트 때문인지」를 구분해 적으면, 이번처럼 표본 탓의 검증 실패로 의견(비싼 호출)이 타는 일을 알아보기 쉽다. 근거는 s4-x2 한 건뿐이라 제안 수준이다.
- 비용 보고서(`CF usage`)에 호출별 캐시 쓰기 토큰을 같이 보이면 캐시 상태 차이를 보고서만으로 읽을 수 있다(이번에는 `claude-usage.json`을 직접 읽었다).

## 더 재려면

- 실행 순서를 바꿔 한 번 더(CLI 먼저), 또는 캐시 TTL(1시간) 이상 간격을 둔 쌍 비교. 예상 비용 $2~3.
- 같은 s4 표본(기준선 실패 테스트를 뺀 저장소)을 Workflow 경로로 돌려 판가름·의견의 경로별 비용을 견준다. 예상 $1.5~2.
