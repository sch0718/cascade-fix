# CF start·go 진행 비용 실측 (2026-10-28)

`docs/2026-10-28-orchestration-cost-design.md`의 (a-lite)(`CF start`·`CF go`, v1.6.1, main 18b57fc)를 작은 표본으로 실제로 돌려 진행 비용(메인 세션이 단계를 이어 가는 몫)이 지적당 얼마로 내려갔는지 쟀다. 이전 측정은 지적당 약 $0.80, 목표는 $0.34 아래다. 코드는 바꾸지 않았다.

## 요약

- **1회, 지적 4건에서 진행 비용은 $1.55(지적당 $0.39), 메인 세션 요청 24건이다.** 이전 $0.80의 약 절반이고 목표 $0.34는 넘는다.
- **줄어든 것은 요청 수가 아니라 맥락 길이다.** 이전 7회는 요청 평균 31건·맥락 평균 약 345k였고, 이번은 요청 24건·맥락 평균 약 111k다(새 맥락의 헤드리스 세션). 같은 24건을 이전 평균 맥락(345k)에서 돌린다고 치면 약 $2.7(지적당 약 $0.68)로 추정한다. 설계안이 센 「요청 약 12건」은 일어나지 않았다.
- 요청이 큰 곳은 Workflow 한 번당 5~6건(`go` 호출, 대기 한 줄, 출력 파일 읽기, 인자 파일 읽기, Workflow, 대기 한 줄)이다. 3절 「발견」 참조.
- 표본이 1회라 목표 달성 여부는 판정할 수 없다. 이 문서가 말할 수 있는 것은 「새 맥락에서는 목표 근처, 긴 세션에서는 아직 멀다(추정)」까지다.

## 방법

이전 측정과 같은 기준(`eval/orchestration_cost.py`의 범위: init(또는 start)를 부른 메시지부터 report까지의 메인 세션 메시지, 하위 에이전트·`detect`·첫 검토 제외, `cascade/usage.py`의 2026-10-06 단가표)을 쓰되 **실행 방식은 다르다**:

| | 이전 7회 | 이번 |
| --- | --- | --- |
| 메인 세션 | 사용자가 실제로 쓴 긴 세션(Opus 5.5) | 새 맥락 헤드리스 `claude -p`(Opus 5.5), 플러그인은 main(18b57fc)을 `--plugin-dir`로 로드, 사용자 설정(CLAUDE.md 등) 기본 로드 |
| 단계 명령 | 개별 명령 | `CF start`·`CF go` |
| 시작 맥락 | 145k~671k(평균 345k) | 87k |
| 권한 | - | `--permission-mode acceptEdits --allowedTools Bash Read Skill Workflow`(분류기가 처음 시도한 `bypassPermissions`·허용 목록 없는 무인 실행을 막아, 사용자가 허용한 뒤 이 설정으로 실행) |

- 프롬프트: 「/cascade-fix 묻지 말고 진행해줘」+ 지적 파일·프로필(`claude-only`)·「Workflow 허락, 외부 전송 안 함, report까지만」. 계획 확인 질문은 이 문구로 건너뛰게 했다.
- 대상: `sample-be`의 커밋 0a21da2f를 임시 워크트리로 뽑고, 기존 표본(`2026-10-26-cost/sample.jsonl`)의 같은 커밋 지적 4건(`pr723-w1`·`w2`·`w3`·`t0`)을 `--source claude-code --findings-json`으로 줬다. 이전 측정에도 같은 4건이 `90d26c0e` 실행(지적 4건, $2.20, 요청 26)으로 있어 같은 규모로 견줄 수 있다.
- 집계: `cascade.usage.read_session`으로 메인 세션 JSONL 전체를 셌다(메시지 id마다 마지막 usage, 1시간 TTL 캐시 쓰기 반영). 세션 시작부터 `CF start`를 부른 첫 요청이라 창이 같다. **`eval/orchestration_cost.py`는 이 세션에서 실행 0회를 냈다**(발견 2). 그래서 같은 함수(`read_session`)를 세션 전체에 쓴 값이다.
- 하위(작업자·판가름·의견) 비용은 진행 비용에 넣지 않았다.

## 발견

코드는 고치지 않았다. 아래는 이번 실행에서 확인한 사실이며, 원인이 확인되지 않은 것은 그렇게 적었다.

1. **`CF start`·`go`를 백그라운드로 돌리라는 것이 SKILL.md의 지시다**(206행, 검증 명령이 Bash 시간 제한을 넘길 수 있다는 이유). 그래서 4번 모두 백그라운드로 불렀고, 그때마다 대기 텍스트 + 출력 파일 읽기 요청이 따라 붙는다(요청 24건 중 Read 4건과 대기 텍스트 8건 안팎). 설계가 센 「단계당 1요청」에는 이 대기 비용이 빠져 있었다. 시간이 짧은 단계만 포그라운드로 부르게 하거나, 대기 알림에 출력을 담는 방법이 후보다(미측정).
2. **`eval/orchestration_cost.py`의 `find_runs`는 백그라운드 호출이면 실행을 찾지 못한다.** `run_dir=`을 `tool_result`에서만 읽는데, 백그라운드 호출의 결과는 작업 출력 파일과 알림으로 와서 이 세션에서는 0회로 나온다. 같은 문제는 `go`가 `GO_REPORTED`를 찾을 때도 생길 수 있다. 이번에는 `read_session`을 세션 전체에 직접 써서 집계했다. 백그라운드 호출을 쓰는 흐름이 흔해지면 도구를 고쳐야 한다(설계 문서 5절 6번의 `find_runs` 보완과 같은 범위).
3. **Workflow를 띄울 때마다 인자 파일(`stage1-args`·`adj-args`·`opinion-args`)을 Read로 열어 그 내용을 스크립트에 넘긴다.** 첫 Workflow는 `run-jobs.js`를 읽고 스크립트를 인라인으로 써서 출력 3,234토큰(약 $0.07)을 썼다. 두·세 번째는 `scriptPath`로 재사용해 464·454토큰이다. 설계 (a-full)(`claude -p`로 Claude 호출)이 없애려는 비용이 정확히 이 부분이다.
4. `ToolSearch select:Monitor`가 1요청 있었다. 알림을 기다리는 데 쓰려 한 것으로 보이지만(추측), 이후 Monitor는 쓰이지 않았다.

## 한계

- **표본 1회·지적 4건**이다. 요청 수와 비용의 분산을 알 수 없다. 이 중 3건은 설계 결정이라 `apply`·재검토·보류 후보 선택이 한 번도 돌지 않았다. 그 단계가 있는 실행은 요청이 더 든다.
- **새 맥락의 헤드리스 세션**이라 이전의 긴 세션과 맥락 조건이 다르다. 절대 지적당 값은 이전 $0.80과 단순 비교가 안 되고, 맥락 보정 값은 추정이다. 사용자가 짧은 세션에서 쓰는 경우의 값에 가깝다.
- 시작 맥락 87k는 이 기기의 사용자 설정(CLAUDE.md·플러그인·도구 정의)이 실린 값이다. 설계안이 가정한 40~60k보다 크다.
- 프로필이 `claude-only`라 의견도 Workflow(3번째)다. `local` 계열은 의견이 Codex 스크립트라 Workflow가 한 번 덜 돌 수 있다(미측정). 이번에는 회사 코드를 외부로 보내지 않으려고 `claude-only`로 했다.
- 같은 모델(Opus 5.5)·같은 단가표지만 `claude -p`가 알려 준 `total_cost_usd`와 `read_session` 합을 메인 세션만 따로 대조하지는 못했다(보고 총액에는 작업자 비용이 섞인다).
- 헤드리스 메인 세션은 SKILL.md의 계획 확인을 프롬프트 문구로 건너뛰게 했다. 실제 사용에서는 계획 확인 한 번이 사람 입력으로 더 붙는다.

## 다음 결정

1. **(a-lite)만으로는 목표를 못 맞춘다고 보는 편이 안전하다.** 새 맥락에서도 $0.39, 긴 세션 추정은 $0.68이다. 요청 수가 12건이 아니라 24건이었다는 것이 핵심 차이다.
2. 값싼 개선 후보(코드·SKILL 수정은 이 문서 밖): 백그라운드 대기 요청 줄이기(발견 1), `go` 출력에 다음 Workflow 인자를 파일 읽기 없이 쓸 수 있는 형태로 남기기(발견 1·3). 한 사이클 6요청이 3~4요청으로 줄면 24건이 약 16건이 되어 새 맥락에서 지적당 약 $0.30으로 내려갈 것으로 추정한다(미측정).
3. (a-full)(`docs/2026-10-28-claude-runner-design.md`)은 발견 3의 비용을 없애므로 방향은 유지하되, 위 값싼 개선의 효과를 먼저 재 보고 (a-full)의 이득이 얼마나 남는지 정한다.
4. 추천 표(`cascade/recommendations.toml`) 갱신은 미룬다. 표본이 1회이고 맥락 조건이 달라 숫자를 옮길 근거가 부족하다.
5. 더 재려면: 같은 방식으로 `local`(의견 Codex)·지적 수가 다른 표본을 2~3회, 한 회당 약 $3.4(메인 $1.55 + 작업자·의견 $1.9)가 든다. 긴 세션 조건은 맥락을 일부러 채운 세션이 필요해 별도 설계가 필요하다. 사용 한도를 쓰므로 승인이 필요하다.
6. `eval/orchestration_cost.py` 보완(발견 2): 백그라운드 호출 결과도 읽도록 한다.
