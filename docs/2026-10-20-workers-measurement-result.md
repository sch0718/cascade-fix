- 맞춘 수는 두 구성 모두 18건으로 같다. 일치율 차이는 분모 차이에서 나온다. 외부 작업자는 정답이 「아님」인 항목 3건(pr723-t5·t6·w1)에서 Codex·Cursor가 둘 다 「사실」로 고쳐 판가름까지 「사실」로 굳었다. Claude 작업자는 같은 항목을 Haiku가 「못 정함」이나 설계 결정으로 올려 사람 목록(판정 없음, 분모에서 빠짐)으로 보냈다.

### Opus 호출이 늘어난 이유

작업자 둘의 1차 결과로 나눈 경로(stage1 결과와 `adj.json` 유무로 다시 셈):

| 작업자 둘의 결과 | Claude 작업자 | 외부 작업자 |
| --- | ---: | ---: |
| 같은 판정, 같은 패치·검증 → 합의(Opus 없음) | 2 | 5 |
| 같은 판정, 패치가 다르거나 한쪽만 검증 통과 → Opus | 14 | 27 |
| 둘 다 설계 결정 → 사람(Opus 없음) | 8 | 1 |
| 둘 다 못 정함 → 사람(Opus 없음) | 2 | 0 |
| 설계 결정 여부가 갈림 → Opus | 5 | 3 |
| 판정이 갈림 → Opus | 6 | 1 |
| **Opus 호출** | **25** | **31** |

- 외부 작업자는 판정이 거의 갈리지 않는다(갈림 1건, Claude 작업자는 6건). 하지만 둘이 각자 다른 패치를 내서, 같은 판정이어도 Opus로 가는 경우가 27건이다(최종 사유는 「패치가 다름」 18, 「한쪽만 검증 통과」 2, 나머지는 Opus 뒤 설계 결정·판단 불가로 끝남).
- Claude 작업자는 둘 다 설계 결정이라고 표시해 Opus 없이 사람에게 가는 경우가 8건이었다. 외부 작업자는 1건이었다. Codex·Cursor는 거의 늘 `needs_design_decision=false`로 답한다.

- CLI 토큰은 사전 추정보다 컸다. 작업당 Codex 입력이 약 19만, Cursor 캐시 읽기가 약 45만이었다. 작업자가 테스트를 돌리고 코드를 읽느라 대화가 길어진다. Cursor `composer-2.5`의 실제 청구액은 대시보드에서 확인해야 한다.
- 중단된 첫 외부 실행(31건)에서도 Codex 입력 515만, Cursor 캐시 읽기 1,196만을 더 썼다.
- 걸린 시간: Claude 작업자 stage1은 병렬로 약 12분 걸렸다. 외부 작업자는 `CF workers`를 한 번에 하나씩 돌려 항목당 약 5분, 37건에 약 3시간이 걸렸다.

## 측정 중 생긴 일

1. **사용자 저장소 변경 검사의 오탐.** 외부 실행 중에 sample-infra의 다른 세션이 sample-be에 브랜치를 fetch하고 지웠다(4개). 그 때문에 31건이 `judge`·`adjudicate`에서 종료 코드 6으로 멈췄다. 트리·HEAD·stash는 바뀌지 않았다. 사용자 결정으로 원장은 고치지 않았고, 31건을 `init`부터 다시 돌렸다(`jobs --force`는 지난 작업자 수정이 남은 워크트리를 다시 써서 쓰지 않았다). 중단된 실행은 `eval/runs/2026-10-19/external-aborted/`에 있다.
2. **Codex 용량 부족.** 첫 실행에서 Codex가 `Selected model is at capacity`로 2번 실패해 Sonnet 대체 실행으로 넘어갔다. 재실행에서는 0건이었다.
3. **Claude Workflow 작업자의 커밋 거부.** 자동 모드 분류기가 작업자 프롬프트의 `git -c core.hooksPath=/dev/null commit --no-verify`를 CI 우회로 보고 막은 경우가 1건 있었다. 패치 추출이 `add -A`를 쓰므로 결과에는 영향이 없었다.
4. **판단불가 사유 표기.** 작업자 둘 다 「못 정함」이면 `consensus`가 사유를 「호출 실패」로 적는다(`cascade/consensus.py:78`). 실제 호출 실패와 구분되지 않는다.
5. **재생용 repos.toml.** 재생에서는 워크트리가 곧 저장소라 `setup`의 `{root}`가 원래 저장소를 가리키지 않는다. `.venv`를 절대 경로로 링크했다. sample-be는 사내 패키지 `sample`이 있어야 테스트가 돈다(사용자가 설치).

## 다음

- 기본값은 바꾸지 않는다. `--workers external`은 옵션으로 남긴다.
- 구조를 되돌릴지, 모델·배정을 바꿔 다시 잴지는 사용자가 정한다. 다시 잰다면 이번 결과가 가리키는 후보는 다음과 같다.
  - Opus 호출: 패치가 달라도 둘 다 검증을 통과하면 판가름 대신 한쪽을 채택하는 규칙을 검토한다(이번 외부 작업자의 「패치가 다름」 18건이 대상 후보). 다만 이 규칙은 Claude 작업자에도 똑같이 적용되므로 두 구성 모두 다시 재야 한다.
  - 일치율: 외부 작업자 프롬프트에 「요구사항·의도가 불분명하면 `needs_design_decision`」 기준을 더 분명히 적는다.
- 검사 오탐(1)과 사유 표기(4)는 측정과 별개로 고칠 거리다.
- 문서 모드는 계획대로 전향 dry-run 비교로 따로 잰다.
