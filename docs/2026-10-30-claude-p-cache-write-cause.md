# `claude -p` 호출당 캐시 쓰기의 원인 대조 실험 (2026-10-30)

`docs/2026-10-30-claude-via-cli-endtoend-measurement.md`에서 `claude -p`(Claude Code 2.1.311) 호출마다 캐시 쓰기 3.4만~3.6만 토큰이 든다고 쟀다. 이 고정비가 사용자 설정(CLAUDE.md·플러그인·MCP·스킬)인지, 기본 시스템 프롬프트인지, 도구 정의인지, 줄일 옵션이 있는지 같은 최소 프롬프트로 변인을 하나씩 바꿔 쟀다. 코드는 바꾸지 않았다.

## 요약

- **캐시 쓰기 3만 토큰 안팎은 「빈 캐시에서 첫 요청이 프롬프트 앞부분(약 2.6만 토큰)을 새로 쓴 값」이다.** 같은 앞부분은 다음 호출에서 캐시 읽기로 바뀐다(1시간 TTL로 기록됨). 같은 호출을 연달아 돌리면 두 번째부터 캐시 쓰기가 호출당 약 7.4k로 줄고 비용이 $0.0070 → $0.0020이 됐다.
- **현재 옵션에서 앞부분의 대부분은 도구 정의로 보인다.** `--tools ""`로 도구를 모두 빼면 첫 요청 프롬프트가 29.8k → 4.5k 토큰이 된다. `ClaudeRunner._command`는 `--allowedTools`/`--disallowedTools`만 쓰는데 이 둘은 자동 허용·거부 규칙이라 모델에 보이는 도구 정의를 줄이지 않았다(도구 25개가 그대로 로드됨).
- **`--tools Bash,Read,Grep,Glob`로 도구 목록을 줄이면 첫 요청 프롬프트 8.3k 토큰(−72%), 콜드 호출 비용 $0.0070 → $0.0019로 줄었다.** 더하여 `--system-prompt`로 기본 시스템 프롬프트를 바꾸면 4.9k까지 줄지만 기본 프롬프트의 안전·도구 사용 지침이 사라지므로 권하지 않는다(아래 위험).
- 사용자 설정은 현재 옵션(`--setting-sources project`)에서 이미 빠져 있다. `user`를 더하면 첫 요청 프롬프트가 +15.8k 토큰(스킬 92개·플러그인 10개·에이전트 15개·CLAUDE.md)이다.
- `--bare`는 있으나 OAuth·키체인을 읽지 않고 `ANTHROPIC_API_KEY`만 쓴다. 이 기기는 API 키가 없어 인증 실패(비용 0)로 효과를 재지 못했다.
- 표본은 호출당 1~3건이다. 통계 결론이 아니라 방향 확인이다.

## 방법

- 호출: `ClaudeRunner._command`(`cascade/runners.py`)와 같은 옵션에 `--model claude-haiku-5-5 --effort low`, 프롬프트 `{"x":1}만 JSON으로 답해`, 스키마 `{"x": integer}`. 빈 임시 작업 폴더에서 실행했다(프로젝트 설정·CLAUDE.md 없음).
- 요청별 캐시 쓰기·읽기를 보려고 `--output-format stream-json --verbose`로 돌려 어시스턴트 메시지마다 `usage`를 기록했다. 최종 `result`의 `usage`는 요청들의 합이라 요청별로 나눌 수 없다. 첫 5건(B0-1·B0-2, V-noslash·V-sysprompt·V-safemode)은 `json` 출력이라 합계만 있고, 아래 표에는 쓰지 않았다(B0-1·2는 「한계」).
- **프롬프트 크기 지표**: 요청 1의 `cache_creation + cache_read`. 캐시 상태와 무관하게 그 요청에 실린 입력 토큰 수라서, 캐시가 따뜻한 변인과 차가운 변인을 같은 눈금으로 비교할 수 있다.
- 호출은 모두 Haiku 5.5 low, 변인 하나씩만 변경했다. 사용자 `~/.claude` 설정은 수정하지 않았다(읽기만).
- 확인한 옵션: `claude -p --help`(2.1.311)와 공식 문서 CLI reference(`--bare`·`--tools`·`--system-prompt`·`--disable-slash-commands`·`--setting-sources`·`--safe-mode`·`--exclude-dynamic-system-prompt-sections`).

## 캐시 재사용 (같은 호출 반복)

`--append-system-prompt cache-probe-…`로 이전에 쓰인 적 없는 프롬프트를 만들고 같은 호출을 이어서 돌렸다.

| 호출 | 시점 | 요청별 (캐시 쓰기, 읽기) | 비용 |
| --- | --- | --- | ---: |
| C-1 | 처음(차가움) | (29,835, 0) → (3,740, 26,142) | $0.0070 |
| C-2 | C-1 직후 | (3,699, 26,142) → (3,746, 26,142) | $0.0020 |
| C-3 | 약 45초 뒤 | (3,696, 26,142) → (3,743, 26,142) | $0.0020 |

- 두 번째 호출부터 앞부분 약 2.6만 토큰은 캐시 읽기다. **호출 간 캐시 재사용은 된다.** 응답 `usage.cache_creation`은 1시간 TTL(`ephemeral_1h`)로 기록됐다.
- 남는 약 3.7k는 요청마다 새로 쓰였다(한 호출 안에서 요청 2도 같은 크기를 또 씀). 이 꼬리는 `--tools …`에서는 약 0.4~0.8k로 줄었다. 무엇이 꼬리를 매 요청 바뀌게 하는지는 확인하지 못했다.
- 같은 방식으로 `--tools Bash,Read,Grep,Glob`: 콜드 $0.0019 → 웜 $0.0005(앱 환경), 최소 환경 웜 $0.0003.
- `--setting-sources`와 도구 목록이 같은 호출끼리만 앞부분을 공유한다고 보인다(변인을 바꾸면 요청 1에서 그 변경분과 뒤따르는 부분이 새로 쓰였다). 정확한 접두 규칙은 확인하지 않았다.

## 미확인

- `--bare`의 효과. 이 기기는 `ANTHROPIC_API_KEY`가 없고 `--bare`는 OAuth를 읽지 않아 호출이 실패한다. 도움말·문서상 CLAUDE.md·스킬·플러그인·MCP·자동 메모리·훅을 건너뛴다고만 확인했다. 현재 옵션이 이미 `project`·`--strict-mcp-config`이므로 `--bare`가 더 줄이는 양은 이 기기에서 재지 못했다.
- 앱 환경이 도구·스킬을 13.1k 토큰 더 얹는 이유(예: `Artifact`·`ArtifactData`·`DesignSync` 같은 앱 쪽 도구). 어떤 환경변수가 원인인지 가르지 않았다. `ClaudeRunner`는 `CLAUDECODE`만 빼고 환경을 물려주므로 앱 안에서 돌리면 이 비용이 든다고 보이지만, 사용자가 터미널에서 `CF go`를 돌릴 때의 값은 「최소」 열이다.
- `--disable-slash-commands`가 프롬프트를 늘린 이유(+6.4k).
- 첫 시도 B0-1·B0-2(같은 호출 연속 2회)는 두 번 다 요청 1이 약 2.6만을 새로 썼다(캐시 쓰기 33.5k·읽기 26.1k, 합계만 기록). C-1·C-2에서는 재사용됐다. 차이의 원인은 모르고 1회씩이라 재현 여부도 모른다.
- Sonnet·Fable 5.1에서의 값. 모두 Haiku 5.5로만 쟀다. 요청 3건(재요청·`--resume`)이 도는 `ClaudeRunner` 경로의 합계 비용도 쟀다기보다 요청별 값으로 추정했다.
- 줄인 구성에서 실제 작업 품질(읽기 도구만으로 지적을 고치는 일)이 달라지는지. 최소 프롬프트만 썼다.
- 이 실험의 `claude -p`는 `--no-session-persistence`를 넣지 않아 세션 기록이 `~/.claude/projects` 아래 임시 작업 폴더 이름으로 남았다가 실험 뒤 지웠다.

## 해석 (가설)

1. 호출당 캐시 쓰기 고정비의 큰 몫은 도구 정의(약 21k 토큰)이고, 기본 시스템 프롬프트가 약 3k, 사용자 설정은 이미 빠져 있어 작은 몫이라는 가설이 이 측정과 맞는다. 도구 정의가 정확히 몇 토큰인지는 도구별로 쪼개 재지 않았다(「`--tools ""`와 `--tools` 4개의 차이」로만 추정).
2. 이전 측정의 「호출마다 3.4만~3.6만 캐시 쓰기」는 캐시가 비어 있을 때의 값일 가능성이 크다. 같은 구성의 호출이 1시간 안에 이어지면 앞부분이 캐시 읽기로 바뀌어 고정 쓰기는 호출당 약 7k(이 실험 기준)로 준다. 반대로 `CF start`처럼 호출이 몇 건 이어지는 흐름에서도 첫 호출만 비싸고 이후는 싸다고 기대할 수 있으나, 모델이 다른 작업자(Sonnet·Haiku)는 캐시를 따로 쓰므로 모델마다 첫 호출이 한 번씩 비싸다고 보인다(확인하지 못함).
3. `--allowedTools`/`--disallowedTools`는 권한 규칙이라 도구 정의 크기를 줄이는 수단으로는 보이지 않는다. 도구를 줄이려면 `--tools`가 맞아 보인다.

## `ClaudeRunner._command` 적용 제안 (이 PR은 코드 변경 없음)

제안: `--allowedTools` 앞에 `--tools`로 모델에 보이는 도구를 읽기 역할은 `Bash,Read,Grep,Glob`, 쓰기 역할은 `Bash,Read,Grep,Glob,Edit,Write`로 제한한다. `--allowedTools`·`--disallowedTools`는 그대로 둔다(자동 허용 규칙과 이중 방어).

| 항목 | 기대 효과 | 위험·확인할 것 |
| --- | --- | --- |
| 비용 | 앱 환경 기준 콜드 호출 −72% 프롬프트(29.8k→8.3k), 호출당 $0.007→$0.002 | Haiku 최소 프롬프트 값이다. Sonnet은 단가가 높아 절대 절감이 더 크지만 재지 않았다 |
| 격리 | 쓰기 도구·`Workflow`·`Skill`·`ToolSearch`·`SendMessage`·`Cron*` 등이 모델에 아예 안 보여 오히려 강해진다 | `--disallowedTools`의 `Agent`·`Task`도 같이 남기면 중복이지만 해가 없다 |
| 동작 변경 | 모델이 `Skill`·`ToolSearch`·`Workflow` 등을 부를 수 없게 된다 | 지금 프롬프트가 이 도구를 기대하지 않는지 확인 필요. 쓰기 역할이 `NotebookEdit`를 필요로 하는 경우는 없다고 보이나 미확인 |
| 구조화 출력 | `--json-schema`가 쓰는 `StructuredOutput`는 `--tools`를 줄여도 남았다(도구 목록에서 확인) | 쓰기 역할·실제 작업에서 재요청 흐름(`--resume`)이 같은지 미확인 |
| 시스템 프롬프트 교체(`--system-prompt`) | 추가로 −3k | 권하지 않음. 기본 프롬프트의 도구 사용·안전 지침이 사라지고, 읽기 전용 격리를 프롬프트에 기대는 부분이 커진다 |
| `--bare` | 이 기기에서 못 재봄 | OAuth를 안 읽어 API 키가 필요하고 `claude` 구독 인증과 달라진다. 도입하지 않는 쪽을 권한다 |

적용한다면 `tests`에서 `_command`의 옵션 배열을 확인하는 기존 테스트를 갱신하고, 읽기·쓰기 각 역할로 `claude -p` 한 번씩 돌려 지적 하나를 고치는 끝단 확인을 한 번 하는 것이 좋다.
