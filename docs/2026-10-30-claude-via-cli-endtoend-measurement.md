# `--claude-via cli` 끝단 실측 (2026-10-30)

`CF start`·`CF go`의 진행 비용을 줄이려고 넣은 `--claude-via cli`(1단계 작업자·점검자·판가름·Claude 의견을 Workflow 대신 `claude -p`로 실행, `cascade/runners.py`의 `ClaudeRunner`)가 실제로 비용을 줄이는지 지적 1건으로 처음부터 끝까지(`start` → `go` → `report`) 돌려 쟀다. 코드는 바꾸지 않았다. 이전 측정은 `docs/2026-10-28-orchestration-cost-measurement.md`다.

## 요약

- **1회, 지적 1건에서 메인 세션 진행 비용은 $0.25(요청 7건), 작업자 호출 비용은 $1.02다.** 작업자 비용의 84%($0.86)는 `--claude-via cli`가 다루지 않는 재검토(Workflow, Fable 5.1) 한 번이다. `claude -p` 호출 2건(작업자 A·B)은 합쳐 $0.16이다.
- **`claude -p` 호출마다 캐시 쓰기 약 3.4만~3.6만 토큰이 든다**(2건 모두). Sonnet 호출 하나($0.154)의 약 88%가 이 캐시 쓰기 추정이다. 호출 수가 줄어도 호출당 고정 비용이 있다는 가설과 맞는다. 다만 Workflow 경로와 같은 표본으로 견주지 못해, 「CLI가 Workflow보다 싸다·비싸다」는 이 측정으로 말할 수 없다.
- 표본이 1회·지적 1건이라 통계적 결론은 없다.

## 방법

- 임시 저장소(`git init`, 파이썬 파일 하나와 pytest 테스트 3개)에 일부러 버그 하나를 심었다: `average()`가 `len(values)+1`로 나눠 `test_average_of_values`가 이미 실패한다. 지적은 이 버그를 가리키는 Warning 1건이다(`--source claude-code --findings-json`).
- 검증 명령은 `~/.claude/cascade-fix/repos.toml`에 임시 항목(`tests`·`full_tests`, pytest)으로 넣었다가 끝난 뒤 백업으로 복원했고, 복원 뒤 임시 항목이 남지 않았음을 확인했다.
- 실행: 이 워크트리의 코드(`PYTHONPATH=<워크트리>`), 프로필 `claude-only`, `start … --claude-via cli` 한 번, 재검토 Workflow 한 번, `go` 한 번. SKILL.md 절차대로 `start`·`go`는 백그라운드로 불렀다. 단계를 줄이지 않았다.
- 메인 세션: 이 세션(Sonnet 5.5)이다. 비용은 `eval/orchestration_cost.py`로 쟀다(`CF start`를 부른 요청부터 report까지, 하위 에이전트 제외, 2026-10-06 단가표). 작업자 비용은 `round-1/claude-usage.json`의 `workflows.cli-stage1-1` 행과 Workflow `wf_e9edbad6-303` 행이다.

| 항목 | 값 |
| --- | --- |
| 실행 | 1회(`cf-20261030-091155`), `claude-only`, `--claude-via cli`, dry-run 아니오 |

이전 측정(지적 4건, 다른 저장소·다른 지적, 새 맥락 Opus 5.5 헤드리스 세션)과 같은 표본이 아니다. 메인 세션 모델(Sonnet 5.5, 시작 시 맥락 약 128k)도 다르고 지적 수도 다르다.

| Workflow 재검토 (Fable 5.1) | $0.860 | 캐시 쓰기 62,510·캐시 읽기 121,455·출력 947 |

- Workflow 횟수는 1회(재검토뿐). 1단계·판가름(합의라 없음)·의견(없음)에는 Workflow가 없었다.
- 메인 요청 7건: `start` 호출, 대기 텍스트, 출력 읽기, 재검토 Workflow, 대기 텍스트, `go` 호출, 출력 읽기. 이전 측정은 같은 용도의 흐름이 요청 24건이었다.
- **`start`가 `jobs`까지가 아니라 1단계 작업과 적용·재검토 인자 생성까지 한 번에 갔다**(CLI 작업 2건 성공, 판정, 적용 1건). Workflow가 필요한 곳(재검토)에서 멈췄다.
- 세션 전체(SKILL.md 읽기 등 준비 포함)의 메인 비용은 $0.86(요청 18건)이고 위 $0.25는 그 부분 구간이다. 작업자 $1.02를 합치면 준비를 포함해 $1.89다. 사용자가 승인한 상한 $1.5의 「메인 비용」을 진행 구간으로 읽으면 $1.27, 세션 전체로 읽으면 상한을 넘는다. 후자로 읽으면 이 문서를 쓰기 전에 이미 넘은 것이다(실측 호출 자체는 진행 구간 읽기에서 상한 안에서 끝났다).

### 가설(호출당 캐시 쓰기 고정 비용)

| 호출 | 캐시 쓰기 토큰 | 호출 비용에서 캐시 쓰기 추정 비중 |
| --- | ---: | ---: |
| `claude -p` Sonnet(A) | 34,033 | 약 88%(1시간 TTL 단가 2배 가정 $0.136 / $0.154) |
| `claude -p` Haiku(B) | 35,595 | 약 51%($0.0044 / $0.0086) |
| Workflow 재검토(Fable 5.1) | 62,510 | 약 91% |

- 비중은 호출별 보고 비용과 `cascade/usage.py` 단가를 맞춰 본 대략값이고(Sonnet은 1시간 TTL 단가, Haiku·Fable은 5분 TTL 단가로 맞아떨어졌다), 캐시 쓰기 TTL 구성은 확인하지 못했다.
- 호출마다 3.4만~3.6만 토큰을 캐시에 새로 쓴 것은 확인했다(2건 모두). 이 값이 사용자 설정(CLAUDE.md·플러그인·도구 정의)에서 오는지 `claude -p`의 시스템 프롬프트에서 오는지는 확인하지 않았다.
- 이 측정에서 말할 수 있는 것은 「`claude -p` 호출 하나는 모델이 싸도 캐시 쓰기 때문에 0.01~0.15달러 이상이 든다」까지다. 요청(지적) 수가 늘 때 이 고정비가 어떻게 늘지, Workflow 에이전트 호출의 캐시 쓰기와 얼마나 다른지는 이 표본으로 모른다.

## 미확인

- 같은 지적을 Workflow 경로(`--claude-via` 없음)로 돌린 비교는 하지 않았다. 재검토가 이미 $0.86이고 Workflow 경로는 1단계 Workflow가 더 있어 한 번 더 돌리면 승인 상한 $1.5를 넘을 것이 확실해서다.
- 판가름·Claude 의견의 CLI 경로는 이번 지적이 합의-사실이라 타지 않았다.
- 호출당 캐시 쓰기의 원인(사용자 설정·시스템 프롬프트·도구 정의)과 `--bare` 등으로 줄일 수 있는지.
- Haiku 호출 비용은 단가표의 Haiku 5.5 값(입력 $0.10/MTok)을 쓴 것이다. 장문 단가가 적용되는지 확인하지 않았다(`project`의 한계와 같다).
- 메인 세션이 Sonnet 5.5이고 사용자 설정이 얹힌 맥락이라 Opus 새 맥락(이전 측정)과 요청당 비용을 직접 견줄 수 없다.

## 해석(가설)

1. 호출당 캐시 쓰기 고정 비용 가설은 「호출마다 3만 토큰 이상 새로 쓴다」는 부분이 맞았다. 비용 영향이 큰지는 Workflow 경로와 같은 지적으로 견줘야 안다(미확인).
2. 이 실행에서 가장 큰 비용은 `--claude-via cli`가 건드리지 않는 재검토 Workflow($0.86, 작업자 비용의 84%)였다. 재검토가 CLI 경로로 옮겨 가는 (a-full) 나머지 단계가 이 비용을 줄일지는 이 측정으로 판단할 수 없다. 재검토는 읽기 전용 격리가 필요해 Workflow로 남겨 둔 것이므로 그 설계 제약은 그대로다.
3. 메인 요청은 `start`가 1단계~적용을 한 번에 했기 때문에 7건으로 줄었다. 이전 측정에서 큰 몫이던 「Workflow 한 번당 5~6건」이 이번에는 재검토 1회에만 해당했다. 지적을 늘려도 1단계가 CLI면 이 몫은 늘지 않는다고 기대할 수 있으나 이번 표본으로는 확인하지 못했다.
