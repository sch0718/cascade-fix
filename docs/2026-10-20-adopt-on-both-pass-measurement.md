# 「둘 다 검증 통과면 한쪽 채택」 측정 결과 (2026-10-20)

`init --adopt-on-both-pass`(코드 모드에서 같은 판정·둘 다 검증 통과·패치가 다르면 판가름 없이 바뀐 줄이 적은 패치를 채택하고, 같으면 a를 채택)를 켰을 때 판정 일치율과 Opus 호출이 어떻게 바뀌는지 2026-10-19 표본(코드 모드 37건)으로 쟀다. 지난 측정은 `docs/2026-10-20-workers-measurement-result.md`(claude/musing-dubinsky-357eed 브랜치)에 있다.

**결과: Opus 호출은 두 구성 모두 크게 준다(Claude 25 → 11, 외부 31 → 10). 일치율은 Claude 작업자에서 오르고(75.0% → 79.2%) 외부 작업자에서 내린다(69.2% → 64.3%). 외부 작업자는 이 옵션을 켜도 비교 기준을 통과하지 못한다(미달: 일치율).**

## 잰 방법: 반사실 재계산

모델을 다시 부르지 않고 지난 실행의 결과에 새 규칙만 다시 적용했다(사용자 결정).

- 지난 두 실행(`eval/runs/2026-10-19/claude`, `external`)의 항목마다 `results.json`의 작업자 a·b 결과(판정·패치)와 `verify.json`의 검증 결과(기준선 실패로 판정에서 뺀 명령은 빼고)를 읽어, 이 브랜치의 `decide()`를 `adopt_on_both_pass`를 끄고 한 번, 켜고 한 번 돌렸다. 보안 경로와 빈 패치 처리(`without_empty_patch`)도 `judge`와 같게 거쳤다.
- 끈 결과가 판가름이면 지난 실행에 `adj-args.json`이 있고, 아니면 없는지 37건×2 모두 대조했다. 모두 맞았다. 재계산이 지난 `judge`의 분기와 같다는 확인이다.
- 켠 결과가 끈 결과와 다른 항목은 원장의 결정을 새 결정으로 바꾸고 Opus 결과(`:adjudicator`, `adj-args.json`, `adj.json`)를 지웠다. 나머지는 지난 결과(판가름을 거친 항목은 그때의 Opus 결과)를 그대로 썼다. 이렇게 만든 폴더를 `eval/score.py`로 채점했다.
- 판가름에 가는 항목에서 Opus가 받는 입력은 옵션과 상관없이 같다. 그래서 남은 판가름은 지난 Opus 결과를 그대로 써도 된다. 작업자 1차 결과의 흔들림(같은 지적을 다시 돌리면 다른 답이 나오는 것)은 이 방법으로는 재지 못한다.

- 나머지 바뀐 항목은 Opus도 작업자와 같은 「사실」을 냈던 경우라 판정은 같다.
- Claude 작업자는 Opus가 틀리게 뒤집은 1건이 바로잡혀 일치율이 올랐다.
- 외부 작업자는 Opus가 사람에게 넘겨 분모에서 빠졌던 「아님」 정답 2건이 「사실」로 채택되어 분모로 들어왔다. 맞힌 수는 18건 그대로라 일치율이 내렸다. 지난 측정에서 본 외부 작업자의 약점(정답이 「아님」인 지적도 둘 다 「사실」로 고친다)을 Opus가 일부 막아 주던 몫이 사라진 것이다.

### 검증 명령이 실제로 테스트를 돌리지 않은 채택

sample-be의 테스트 명령은 `test -z "{files}" || pytest {files}`다. 바뀐 파일과 관련된 테스트 파일이 없으면 `{files}`가 비어 명령이 아무것도 돌리지 않고 성공한다. 규칙은 「검증 명령이 하나도 없으면 판가름」만 보므로 이 경우를 둘 다 검증 통과로 본다.

| 구성 | 항목 | 정답 | a 검증 | b 검증 |
| --- | --- | --- | --- | --- |
| 외부 | rsbe-pr723-t4 | 아님 | 테스트 없음 | 테스트 없음 |
| 외부 | rsbe-pr723-t5 | 아님 | 테스트 없음 | 테스트 없음 |
| 외부 | rsbe-pr723-w1 | 아님 | 테스트 없음 | 테스트 없음 |
| 외부 | rsbe-pr723-t6 | 아님 | 테스트 있음 | 테스트 없음 |

- 외부 작업자에서 이 규칙으로 채택한 21건 중 3건은 양쪽 모두, 1건은 한쪽이 테스트를 돌리지 않았다. 네 건 모두 정답이 「아님」이다. Claude 작업자의 14건은 모두 양쪽이 테스트를 돌렸다.
- 이 네 건 중 t5·t6·w1은 지난 실행에서도 Opus가 「사실」로 굳혔으므로 일치율 변화에는 들어가지 않는다. 하지만 규칙을 켜면 실제 검증 없이 패치가 채택된다.

### 채택한 패치

- 바뀐 항목 35건(Claude 14, 외부 21) 중 Opus가 작업자 패치 하나를 고른 경우는 없었다. 「사실」로 끝난 경우 Opus는 매번 자기 패치(`patch_from=adjudicator`)를 냈다. 그래서 규칙이 고른 작은 패치와 Opus 패치가 같은지는 이 측정으로 말할 수 없다. 판정 일치율만 비교했다.
- 회귀는 소급 재생이 dry-run이라 재지 못했다.

## 해석

- Opus 호출 절감은 확실하다. Claude 작업자 56%(25 → 11), 외부 작업자 68%(31 → 10)가 준다. 외부 작업자의 Opus 호출이 Claude 작업자 실행보다 많던 문제(지난 미달 사유 하나)는 사라진다.
- 일치율은 구성에 따라 방향이 다르다. Claude 작업자는 +4.2%p, 외부 작업자는 −4.9%p다. 둘 다 항목 1~2건 차이라 표본이 작다는 한계는 그대로다.
- 외부 작업자는 옵션을 켜면 Claude 작업자(켬)와의 일치율 차이가 5.8%p에서 14.9%p로 벌어져 비교 기준에서 더 멀어진다.

## 다음

- 실측(두 구성을 옵션을 켜고 실제로 다시 돌리기)은 이 결과를 보고 사용자가 정한다. 실측은 작업자 1차 결과의 흔들림까지 포함하지만 비용이 든다(지난번 기준 Claude 서브에이전트 약 740만 토큰, 외부 약 3시간과 Codex·Cursor 토큰, 표본 코드의 OpenAI·Cursor 전송). 돌린다면 `eval/replay.py --adopt-on-both-pass`로 `init`에 옵션을 넘긴다.
- 고칠 거리(이 측정 범위 밖):
  - 규칙이 아무것도 돌리지 않은 검증 명령(`test -z ""`처럼 대상 파일이 없어 그냥 성공)을 검증 통과로 본다. 실제로 테스트가 돌았는지 구분해 판가름으로 보낼지 정해야 한다.
  - `score.py`의 「패치 다르지만 둘 다 통과」 줄은 사유 「패치가 다름」만 센다. 옵션을 켠 실행에서는 이 규칙으로 채택한 항목(사유 「둘 다 검증 통과」)이 빠져 0으로 나온다.
